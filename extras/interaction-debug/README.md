# Sunday Inputs → Debug

Shows only the last three voice/Telegram interactions using existing cost-turn records as the chronological index. Joins request hashes to existing bounded receipts, then exact request IDs to Fast Mode attempts and World action receipts. Model calls are correlated by their existing request_ref. Displays transcript, final reply, routing decision/fallback reason, model rounds/token/cache information, tool arguments/results, candidate resolution, plan, presence, exclusions and action outcomes.

Timings come from existing Fast Mode and cost ledgers plus bounded journal windows. Mic timings require an exact matching transcript near the turn start. Backend first-text log timing must match its relative wall-clock timestamp, and is omitted on detected overlap. Capturing/end-of-speech duration is explicitly inferred; first text is not audible speech. Brain duration and voice response through playback overlap. Separate TTS synthesis/playback measurements are unavailable and shown as Not logged, never invented. Some existing tool results were redacted upstream and cannot be reconstructed. Debug data is read-only evidence, not internal/private model reasoning.

Performance: no changes to production voice/wake/brain/model/output source, no production service restarts, no added instrumentation, no extra model calls, no recording or playback. The independent diagnostics API performs work only when the view opens or Refresh is clicked. No polling timer; HA state updates do not trigger new reads. SQL connections use mode=ro/query_only with a 25 ms busy timeout. Journal reads are limited to narrow windows, capped at 1200 lines per interaction, run at nice 19, and have a four-second limit. Collector runs in a separate worker thread in the existing diagnostics service, not on Sunday's request path. Same-turn snapshots have a 15-second cache. Reading still uses a small amount of shared CPU/I/O; measured initial snapshot approximately 0.16 s. It is not literally zero host resource use.

Authenticated loopback endpoint: POST http://127.0.0.1:8097/v1/interaction-debug, reached through HA rest_command.sunday_interaction_debug. Existing daemon authorization and admin dashboard access used. Sensitive credential fields/patterns redacted; frontend text rendered through textContent. Local sample/test artifacts are protected by this directory's 0700 permissions. No debug snapshots sent to Telegram automatically.

Verified: six collector tests (last-three ordering/correlation, read-only DB fingerprints, missing-source behavior, unknown timings, exact transcript/overlap handling, cache and credential redaction), twelve existing diagnostics/alias tests, real HA REST response, three real mobile cards, layout, manual Refresh and no reread on repeated hass state pushes. Production source hashes and service PIDs unchanged, recorded in deployment.json. Brain ready/Telegram running. First publication check raced diagnostics-server startup; deployment script now waits for its authenticated endpoint before publishing. Browser checks passed after publication.
